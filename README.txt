ets2fast — ETS2 载入加速（不修改游戏文件，不修改任何 mod）
==========================================================

怎么用（就两步）
----------------
1. 双击 ets2fast.exe
2. 按 1，回车

完成。以后从 Steam 点「开始游戏」就会自动注入，不用再开任何程序。
开机后也自动生效，不需要每次手动操作。

想改回手动方式：再双击 ets2fast.exe，按 2，回车。
之后每次玩之前先双击 inject.exe，再从 Steam 启动游戏。

程序会记住自己的位置。整个文件夹可以随便移动，移动后重新按一次 1
即可（菜单会提示「开机自启里记录的是旧路径」）。


菜单里三个键干什么
------------------
[1] 开启自动注入
    在后台启动一个守护进程，并登记为开机自启。
    守护进程只做一件事：发现 eurotrucks2.exe 启动就注入，然后继续等
    下一次。不改 Steam 配置、不改游戏文件、不需要管理员权限。

[2] 关闭自动注入
    删除开机自启，结束守护进程。回到「先开 inject.exe」的手动方式。

[3] 查看状态与日志
    显示当前状态，以及两个日志文件的末尾内容。


效果（同一台机器、同样 58 个 mod 实测）
--------------------------------------
                        无工具      有工具
mod 就绪 → 可驾驶        60.97 秒    29.23 秒

其中「公司货物分配」一段从 38.13 秒降到 15.20 秒，因为一次载入里有
180 万次「查一个不存在的文件」被内存查表直接挡掉，不再进内核。


原理
----
ETS2 的虚拟文件系统没有索引：每个资源都要在每一个 mod 层里逐层试
「你有吗」。实测一次启动 425 万次文件操作，98.6% 是 PATH NOT FOUND。
本工具在进程内维护一份 workshop 路径表，直接内存判定，命中即返回。

守护进程只是负责「在游戏启动的那一刻把 DLL 塞进去」，加速本身全部
发生在游戏进程内部，所以对启动方式没有任何要求。


为什么用守护进程，而不是包装 Steam 启动选项
-------------------------------------------
包装方式（%command%）会把游戏变成启动器的子进程，Steam 的游戏内叠加
界面（F12 截图、好友浮层）可能不显示。

守护进程方式下，游戏仍由 Steam 直接启动，叠加界面不受影响，而且顺手
解决了另一件事：不管你是从 Steam、桌面快捷方式还是别的什么地方启动，
都能生效。


换台电脑也能用
--------------
* DLL 不依赖任何写死路径：它从自己被加载进的那个进程（eurotrucks2.exe）
  的位置一路向上找名为 steamapps 的目录，再拼出 workshop\content\227300。
  游戏装在哪个盘、哪个 Steam 库，都不用配置。
* 开机自启只写 HKEY_CURRENT_USER，不需要管理员权限，也不会弹 UAC。
* 所有 exe 全静态链接，不依赖 VC++ 运行库或 MinGW 运行库，纯净系统也能跑。

特殊布局（极少见）可以用环境变量强行指定 workshop 目录：
    set ETS2FAST_ROOT=H:\SteamLibrary\steamapps\workshop\content\227300\

给别人用：整个文件夹打包发过去，他双击 ets2fast.exe 按 1 就能用。


卸载 / 恢复原版
--------------
双击 ets2fast.exe → 按 2（清掉开机自启和守护进程）→ 删掉文件夹。

游戏目录里没有本工具的任何文件，Steam 的「验证文件完整性」也不会
报缺文件。


文件说明
--------
ets2fast.exe       菜单程序，双击这个
ets2fastd.exe      后台守护进程（无窗口，由菜单启动，开机自启跑的也是它）
ets2fast.dll       拦截逻辑，被注入进游戏进程
inject.exe         手动方式：等你启动游戏，然后注入一次，有状态输出
README.txt         本文件
LICENSE            MIT 许可证

如果 Steam 启动选项里还留着旧的配置
------------------------------------
早期版本用「包装启动选项」的方式，配置长这样：

    "…\ets2fast.exe" --launch %command%

如果还留着，请删掉它（Steam 库 → 右键游戏 → 属性 → 通用 → 启动选项），
只保留 -nointro 之类的参数。否则游戏会被启动两次。

没删也不会出错：ets2fast.exe 收到 --launch 时会自动转交给 ets2fastd.exe
按包装方式处理，只是那种方式下叠加界面可能不显示。

菜单的 [1] 会自动检查这个配置，发现残留会提醒你。


日志与诊断
----------
ets2fast.log             DLL 写的：选了哪个 workshop 目录、索引条数、
                         hook 是否装上、每 60 秒一行 blocked/passed 计数
ets2fast-launcher.log    守护进程 / 注入器写的：发现游戏、注入结果、退出码

判读方法：ets2fast.log 里出现
    root (derived from game path): ...     ← 自动找到了 workshop
    hook installed                          ← 挂钩成功
之后 blocked 会迅速增长、passed 基本不动，说明拦截在生效。
如果 blocked 一直是 0，或出现 "root: NOT FOUND - no hook installed"，
把日志发出来看。

调试模式（记录前 300 条被拦路径）：
    set ETS2FAST_DEBUG=1


安全性设计
----------
* 只拦「能证明不存在」的路径：从 mod id 开始逐级必须存在，遇到不认识的
  层级一律放行，索引不完整也不会误伤。
* 返回的错误码与系统原生一致：末级文件缺失返回 2，中间目录缺失返回 3，
  游戏内部按错误码分支的逻辑不会改变走向。
* 任何带写权限的打开请求一律放行。
* 索引为空或扫描失败时根本不安装 hook，游戏行为等同原版。
* 目录监听：游戏运行中新增/删除 mod（订阅、Steam 下载、点「确认更改」
  热重载）会被检测到 —— 立即停止拦截、等几秒静默、重建索引、自动恢复，
  不需要重启游戏。
* 注入失败不会影响游戏：最坏情况就是没有加速，游戏照常运行。
* 守护进程只写自己的日志和 HKEY_CURRENT_USER 里那一个开机自启项，
  不碰系统目录、不碰游戏目录、不碰任何 mod。
* 手动方式（inject.exe）用 Job 对象绑定游戏进程：在 Steam 里点「停止」
  会连同游戏一起结束，不会留下孤儿进程。


实测兼容性
----------
游戏 bin\win_x64 里同时存在：
    dxgi.dll        ReShade 6.8.0（hook user32 / d3d9-12 / dxgi / dinput）
    steam_api64.dll cream_api 5.1.0（只代理 Steam API）
    version.dll     Juij 加载器
    winmm.dll       Juij 加载器
    dstorage.dll    SCS 官方 DirectStorage
五个 DLL 均未引用 NtCreateFile / NtOpenFile，与本工具不重叠。

链式行为也验证过：若别的工具先 hook 了 NtCreateFile，本工具会读取当时
的跳转目标作为「原始实现」，接在它之上调用，两个钩子都会触发，不覆盖。
反向（别人在本工具之后再 hook）最坏只是本工具失效，不会报错。

本包内所有 exe / dll 均为全静态链接，只依赖 KERNEL32 和 Windows 10/11
自带的 UCRT，不需要 VC++ 运行库，也不需要 MinGW 运行库。


已知限制
--------
* 只处理绝对路径。游戏目前全是绝对路径；若将来某处用相对路径，那部分
  只是不加速，不影响正确性。
* 只 hook NtCreateFile。若游戏改用 DirectStorage 读 mod（目前仅用于官方
  .scs），拦截会失效 —— 表现为加速变小，不会出错。
* Windows 大版本更新可能改变 ntdll 导出形式，代码同时支持 Win11 的
  thunk 形式（48 B8 <imm64> FF E0）和传统 syscall stub 形式，两种都实测
  装成功；游戏更新后看一眼日志里的 hook installed 即可确认。
* 守护进程常驻，内存占用约 9 MB，每 250 毫秒查一次进程列表。
